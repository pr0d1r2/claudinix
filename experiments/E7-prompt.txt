Experiment E7 (claudinix experiments/SPEC.md T62): do cloud sessions stop on
the "Allow Claude to use add repo (claude-code-remote)?" prompt once the exact
rule is committed in the target repository, and does `--permission-mode` with
`--cloud` change that?

Part A, rule committed (needs a branch of pr0d1r2/sherd):
1. On a sherd branch, commit `.claude/settings.json` holding only
   {"permissions":{"allow":["mcp__claude-code-remote__add_repo"]}}.
   The rule does not limit arguments, so it allows `access: "push"` on any
   repository the session's GitHub grant reaches. Before step 2, create two
   throwaway repositories for E7 (one public, one private) and limit the
   grant to sherd and those two.
2. Start a Sonnet cloud session on that branch. Record the exact launch
   command with `--model sonnet`, or that the UI selected Sonnet. Ask it to
   call `add_repo` twice, each with `access: "push"`: once on the public and
   once on the private throwaway repository. Record, per call, the exact
   arguments sent and whether a prompt appeared.

Part B, flag (the raw `claude --cloud` is deliberate here: it is the thing
under test, so AGENTS.md's `just cloud` rule does not apply to E7):
   <task> is the step 2 request word for word, on the same sherd branch,
   with the same committed `.claude/settings.json`, GitHub grant and
   `add_repo` arguments; only the flag changes.
3. Run `claude --cloud "<task>" --model sonnet --permission-mode dontAsk`.
4. Run `claude --cloud "<task>" --model sonnet --permission-mode acceptEdits`.
   For each of steps 3 and 4 record separately: whether the flag is
   accepted, whether the session starts in that mode, and whether the
   add_repo prompt still appears.

Report per step: the exact command, prompt yes/no, the error line if any.
